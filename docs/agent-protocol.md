# droidrt automation contracts

This document defines how the three automation pieces talk to each other:

1. `agent-apk/`: the on-device agent (AccessibilityService and NotificationListenerService) installed in the VM.
2. `droidrt_mcp/`: the MCP server on the Mac. It drives the agent and adb, and exposes tools to MCP clients.
3. `semantic/`: per-app tools derived from APK analysis, curated definitions and recorded flows.

## 1. Device agent protocol

- **Package:** `dev.droidrt.agent`, with services `.AgentService` (accessibility) and `.NotifyService` (notification listener).
- **Transport:**
  - The agent listens on the abstract local socket `droidrt_agent`.
  - The host reaches it with `adb -s <serial> forward tcp:<port> localabstract:droidrt_agent`.
  - Messages are newline-delimited UTF-8 JSON, one message per line. A line may not exceed 1 MiB (1048576 bytes, newline excluded); a longer line closes the connection.
  - Only peers with uid 0 (root) or 2000 (shell, which is what `adb forward` connections come from) are accepted. Other peers are disconnected before any byte is exchanged.
  - Every connection starts with the handshake below. After it, several requests may be pipelined on a single connection, and responses keep the order of the requests.
- **Key delivery:**
  - The key is 32 random bytes generated by the host, written as 64 hex characters. For HMAC the key is the 32 decoded bytes, not the hex text.
  - The host delivers it with:
    ```sh
    adb shell am broadcast -a dev.droidrt.agent.SET_KEY -n dev.droidrt.agent/.KeyReceiver --es key <64hex>
    ```
  - `.KeyReceiver` is exported but protected by `android:permission="android.permission.DUMP"`: the adb shell holds it, regular apps do not.
  - The broadcast result code is `1` when the key was stored and `0` when it was rejected (anything but exactly 64 hex characters). `am` prints it as `Broadcast completed: result=1`.
  - The key is kept in the agent's private SharedPreferences. A new broadcast replaces it (rotation); connections already authenticated are not affected.
- **Handshake** (per connection; HMAC is HMAC-SHA256 over the UTF-8 text, hex is sent lowercase and accepted in either case):
  1. Agent, right after accepting: `{"hello": "droidrt-agent", "v": 2, "nonce": "<agentNonce>"}`, where `agentNonce` is 16 bytes from `SecureRandom` as 32 hex characters.
  2. Client, first line: `{"auth": "<hex HMAC(key, \"client:\" + agentNonce)>", "nonce": "<clientNonce>"}`, where `clientNonce` is 16 fresh random bytes as 32 hex characters.
  3. Agent:
     - Success: `{"ok": true, "proof": "<hex HMAC(key, \"agent:\" + clientNonce)>"}`. The client must compare `proof` in constant time and close the connection if it does not match. Normal requests follow.
     - No key configured: `{"ok": false, "error": "no key"}`, then close.
     - Wrong HMAC: `{"ok": false, "error": "auth failed"}`, then close.
     - A first line that is not a JSON object with a 64 hex `auth` and a 32 hex `nonce` (for example `POST / HTTP/1.1`, or a regular request): close immediately, without a reply and without processing anything.
  - The agent compares `auth` in constant time (`MessageDigest.isEqual`).
  - The handshake must finish within 10 seconds of the connection being accepted, or the agent closes it. There is no timeout after authentication.
- **Request:** `{"id": <int>, "cmd": "<name>", "args": {...}}`
- **Response:**
  - Success: `{"id": <int>, "ok": true, "result": ...}`
  - Failure: `{"id": <int>, "ok": false, "error": "<message>"}`
- **Enabling the services** (the host runs this after install, then delivers the key). The MCP server reads `enabled_accessibility_services` first and appends `dev.droidrt.agent/.AgentService` with a `:` separator, so services that are already enabled stay on. The plain form below replaces the list and is only suitable for a fresh VM:
  ```sh
  adb shell settings put secure enabled_accessibility_services dev.droidrt.agent/.AgentService
  adb shell settings put secure accessibility_enabled 1
  adb shell cmd notification allow_listener dev.droidrt.agent/dev.droidrt.agent.NotifyService
  ```

### Commands

| cmd | args | result |
|---|---|---|
| `ping` | none | `{"version": "2", "sdk": 37}` |
| `displays` | none | `[{"displayId": 0, "width": 1080, "height": 2400, "packages": ["..."]}]` (display ids come from `AccessibilityService.getWindowsOnAllDisplays()`) |
| `tree` | `{"displayId": int?, "package": str?, "maxDepth": int?, "visibleOnly": bool? (default true)}` | see "Node" below. When `package` is given, only that package's windows are returned, whatever the display. |
| `find` | `{"displayId"?, "package"?, "text"?, "textContains"?, "resourceId"?, "contentDesc"?, "className"?, "clickable"?}` | list of Node (no children) |
| `action` | `{"nodeId": str, "action": "click" \| "long_click" \| "focus" \| "set_text" \| "scroll_forward" \| "scroll_backward" \| "select" \| "clear_text" \| "ime_enter", "text"?: str}` | `{"performed": bool}` |
| `tap` | `{"displayId": int, "x": int, "y": int, "durationMs"?: int}` | `{"performed": bool}` (dispatchGesture on that display) |
| `swipe` | `{"displayId": int, "x1", "y1", "x2", "y2", "durationMs"?}` | `{"performed": bool}` |
| `global` | `{"action": "back" \| "home" \| "recents" \| "notifications"}` | `{"performed": bool}` |
| `notifications` | `{"package"?: str, "sinceMs"?: int}` | list of `{"key", "package", "postTime", "title", "text", "subText", "actions": [{"index", "title", "remoteInput": bool}]}` (active notifications plus a ring buffer of the last 200 posted) |
| `notification_action` | `{"key": str, "index": int, "text"?: str}` | `{"performed": bool}` (fills RemoteInput with `text` when the action has one, for example quick reply) |
| `wait_idle` | `{"timeoutMs"?: int, "idleMs"?: int}` | `{"idle": bool}` (returns once no accessibility events arrived for `idleMs`) |

### Node

```json
{"id": "w12:0.3.1", "cls": "android.widget.Button", "pkg": "com.whatsapp",
 "text": "Agree and continue", "desc": null, "rid": "com.whatsapp:id/eula_accept",
 "bounds": [x1, y1, x2, y2], "displayId": 10,
 "clickable": true, "editable": false, "scrollable": false, "checked": null,
 "enabled": true, "focused": false, "selected": false, "password": false,
 "children": [ ... ]}
```

- **`id`:** the window id plus the child index path. It stays valid until the window content changes. If a node goes stale, the agent answers with `"error": "stale node"`, and the host calls `tree` again.
- **`children`:** omitted for leaves. Empty strings become `null`.

## 2. Semantic tool definitions

The `semantic/` package exposes:

```python
def tools_for(package: str, apk_paths: list[Path] | None = None) -> list[dict]
```

Each tool is a dict:

```json
{"name": "whatsapp_draft_message",
 "description": "Open the WhatsApp chat with a phone number and prefill a message without sending it",
 "package": "com.whatsapp",
 "inputSchema": {"type": "object", "properties": {"phone": {"type": "string"}, "text": {"type": "string"}}, "required": ["phone", "text"]},
 "action": { ... }}
```

### Action types

The MCP server executes these:

- **`intent`:** `{"type": "intent", "action": "android.intent.action.VIEW", "data": "https://wa.me/{phone|digits}?text={text|urlencode}", "package": "com.whatsapp", "component": null, "extras": {"k": "{arg}"}, "mimeType": null, "categories": []}`
  - Runs through `am start -W --display <id>` on the app's display.
  - The intent always targets the tool's own app: `package`, when set, must be that app, and `component` must belong to it.
  - Templates use `{arg}` and support the filters `|urlencode` and `|digits` (strips non-digits). Filters can be chained.
- **`flow`:** `{"type": "flow", "steps": [ ... ]}`. Each step is an object with exactly one key:
  - `{"open_app": pkg}`, where `pkg` must be the tool's own package
  - `{"intent": {...}}`, with the same rules as the `intent` action
  - `{"wait": {selector, "timeoutMs": 10000}}` (`timeoutMs` from 1 to 300000)
  - `{"tap": {selector}}`
  - `{"type": {"selector": {...}, "text": "{arg}"}}`
  - `{"press": "back" | "enter" | "home"}`
  - `{"swipe": {"direction": "up" | "down" | "left" | "right"}}`
  - `{"sleep": ms}` (0 to 120000)

  A flow has at most 200 steps. Step selectors use the `find` arguments of the device agent **except `package` and `displayId`**: `text`, `textContains`, `resourceId`, `contentDesc`, `className` and `clickable`. A selector that sets `package` or `displayId` is rejected, and the engine always pins every step to the tool's own package, so a flow cannot act on another app.

### Sources, in order of precedence

1. Curated definitions in `semantic/curated/<package>.json` (for example WhatsApp, with `whatsapp_open_chat`, `whatsapp_draft_message`, `whatsapp_send_message` and `whatsapp_share_text`).
2. Recorded flows in `~/Library/Application Support/droidrt/flows/<package>/<name>.json`, written by the `record_flow` tool. A file holds either a full tool definition or the short form `{"description", "inputSchema", "steps"}`.
3. Tools generated from the manifest (at most 15 per app): browsable deep links (`<data scheme host pathPrefix>` with BROWSABLE), exported activities with intent filters, and `ACTION_SEND` share targets.

Tool names are sanitized to `^[a-z0-9_]{1,64}$` and prefixed with a short app slug. When two sources produce the same name, the higher precedence wins.

### Notifications as returned by the MCP server

The MCP tool `get_notifications` does not pass the agent's `notifications` list through unchanged. It drops packages the server may not access and returns:

```json
{"count": 3,
 "notifications": [{"key": "...", "package": "com.whatsapp", "postTime": 0, "title": "...", "text": "...",
                    "subText": null, "actions": [{"index": 0, "title": "Reply", "remoteInput": true}]}],
 "truncated": true}
```

- `count` is the number of matching notifications before any cut.
- `notifications` holds at most 50 entries and about 100 KB of JSON; text fields are cut at 2000 characters and action titles at 200, with at most 16 actions per notification.
- `truncated` is present, and `true`, only when entries or text were left out.
